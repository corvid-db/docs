Functions: lifecycle & values

Conventions used throughout the function pages: corvid_status return unless stated; (const char* s, size_t len) = borrowed, binary-safe, UTF-8 where the engine takes &str; NULL pointer with len > 0 is CORVID_E_ARGUMENT, NULL with len == 0 is empty only where marked nullable; const corvid_value* inputs are CLONED — the caller keeps ownership.

Lifecycle & errors (8)

Section titled “Lifecycle & errors (8)”

Returns 1. No engine counterpart — pure ABI versioning. Bindings verify this before anything else.

Open (creating if absent) a file-backed database. Wraps Db::open. Returns the handle, or NULL + CORVID_E_DATABASE / CORVID_E_INCOMPATIBLE_FORMAT / CORVID_E_IO (non-UTF-8 paths answer CORVID_E_ARGUMENT — the universal UTF-8 rule).

In-memory database. Wraps Db::open_in_memory.

Releases the handle’s reference. Persistence is durable per-transaction — no explicit close/flush exists in the engine either. Freeing the db while rows/iterators from it are live is fine (they own their data).

Thread-local last error — NULL message when none recorded. See errors.

The ONLY buffer deallocator — for ABI-returned buffers (corvid_insert_auto keys, corvid_page’s next_after cursor). Does NOT free handles or values. corvid_free(NULL) is a no-op.

User collection names (engine __ namespaces excluded), name order, as a string cursor. Listing creates nothing (collections are lazy on first write).

Collection handles (3)

Section titled “Collection handles (3)”

corvid_collection returns NULL only on NULL arguments; reserved/invalid names fail at write time (lazy validation, as in Rust). The name is BORROWED from the handle until corvid_collection_free.

Value construction (11)

Section titled “Value construction (11)”

All constructors return an OWNED corvid_value* or NULL + CORVID_E_ARGUMENT. Byte/text/vector inputs are CLONED into the value.

  • array_push/map_put consume item/val (ownership moves in; do not free them afterwards). Single-threaded mutation of the container.
  • A duplicate map key REPLACES the previous entry (last write wins; the replaced child is dropped). Map order in the engine is sorted by key — construction order never matters.
  • Pushing/putting invalidates previously borrowed children of the container (see ownership).

Value reads (13)

Section titled “Value reads (13)”

Wrong type sets *ok = 0 and returns 0 — not an error (mirrors the Rust Option accessors).

Zero-copy BORROWED views. NULL when the value is a different type (not an error). Valid until the parent value is freed or mutated — writing through these pointers is UB.

BORROWED children; NULL when out of range / absent / wrong container (not an error). Child lifetime rides the parent — freeing a borrowed child is UB.

The map’s keys as an OWNED string cursor (added in 0.3.0), in ascending key-BYTE order — the engine’s BTreeMap iteration order. Drive it with corvid_strs_next / corvid_strs_free (see graph & geo); each key is UTF-8 handed out as a binary-safe (pointer, length) pair borrowed until the cursor’s next next or its free. A non-map v yields an EMPTY cursor — inert, not an error (the as_* wrong-type convention). NULL v answers NULL + CORVID_E_ARGUMENT.

corvid_value_clone is the sanctioned way to keep data observed through a borrowed pointer (e.g. a rows document) beyond the parent’s lifetime. corvid_value_free on a borrowed child (from _ref, array_get, map_get, rows_next, geohits_next, callbacks, or already-consumed push/put inputs) is undefined behavior.
